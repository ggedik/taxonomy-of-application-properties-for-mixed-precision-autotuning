WHY THE SEARCH CAN BE HARD

Every stage depends on your application.

The poster’s four property categories explain what can make the same workflow straightforward in one code and difficult in another.

01 / STRUCTURECan you isolate the work?

Kernels, loops and data structures define tuning atoms. Deep call chains and irregular data flow increase profiling and search costs. Choosing finer granularity can also add casts.

Workflow impact: profiling & search
02 / BEHAVIORDoes the execution path change?

Precision can alter convergence, adaptive choices or run-to-run variability. A final-output check may need to be supplemented with trajectory checks, repeated runs or representative inputs.

Workflow impact: validation
03 / NUMERICALWhat makes an answer acceptable?

Residuals, invariants or domain-specific scores define the correctness oracle. Sensitivity and recovery mechanisms determine how conservatively the search must proceed.

Workflow impact: search-space reduction
04 / PERFORMANCEDoes the change address the bottleneck?

Low-precision arithmetic helps only when it addresses the actual bottleneck. Memory traffic, casts, compiler effects and recovery work can erase a potential gain.

Workflow impact: evaluation
THE POSTER’S FALSE FRIEND

Correct can still mean unprofitable.

A deterministic stencil looks promising. Data may need to stay in high precision because other parts of the computation depend on it. With storage kept in FP32, computing this kernel in FP16 adds conversions without reducing memory traffic.

In the poster’s instruction-level example, conversion and packing demand outweighs the arithmetic saving. Passing correctness is only one gate.

Rounding and validation

After each iteration, the relative residual ‖b − Ax‖₂ / ‖b‖₂ is evaluated with JavaScript’s native FP64 arithmetic. This independent check prevents low-precision arithmetic from reporting a misleading zero residual. Starting values, updates, and intermediate subtraction and division are rounded in the selected precision.

A repeated state or two-cycle above the target is reported as stalled. Runs stop after convergence, stagnation, or 40 iterations. This example does not model hardware performance.
