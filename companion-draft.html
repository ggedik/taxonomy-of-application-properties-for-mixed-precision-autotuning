    03 / THE FALSE FRIEND

    Half the bits.
    Twice the speed?

    A regular stencil kernel. Deterministic output. Simple arithmetic. Three properties look favorable.

    Data may need to remain stored in high precision because other parts of the computation depend on it. Now keep storage in FP32 and lower only the arithmetic to FP16. What happens?

    Intel Sapphire Rapids · F16 / AVX512
    FP32Storage + compute

    FP16Compute only

    Make your prediction

    In the poster’s instruction-level example, conversion and packing costs outweigh the arithmetic saving.

    Change in RT cycle demand shown in the poster; this is an instruction-level illustration, not a measured end-to-end speedup.

    Why does this happen?

    Storage stays FP32, so memory traffic is not reduced. Loading FP32 values, converting and packing them into FP16, then converting the result back adds work. Processing 32 FP16 elements per ZMM does not guarantee a useful gain.

    The example counts 15 conversion/pack operations per 32 outputs, versus only 2 cycles saved in arithmetic. Operations and cycles are different units; the bars above use the poster’s cycle-demand figures.
